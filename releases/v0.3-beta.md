# HakiOS on the OnePlus 6T — Beta 0.3 (`v0.3-beta`)

November 2026. Kernel: [`kiwiiiii-eth/hakios-xnu-kernel`](https://github.com/kiwiiiii-eth/hakios-xnu-kernel/tree/fajita-v0.3-beta),
tag `fajita-v0.3-beta`. Device: this repository, tag `v0.3-beta`.

Still a developer bring-up, as Beta 0.2: tethered to a Mac over USB, the whole system in RAM (nothing is flashed; a reboot
goes back to Android), built on your Mac with your own IPSW and your own phone's firmware. No Apple software and no vendor
firmware are distributed here.

## What is new since Beta 0.2

- **Safari loads pages.** In Beta 0.2 a page spun for ever (or stayed blank) although the network worked. WebKit had in
  fact loaded and drawn it; Safari's main thread was waiting on AppleMediaServices, which waited on `apsd`, which waited
  on `mobileactivationd` — a daemon that traps at every start on this phone and never answers what is queued for it.
  It is now left out, and everything that asks it gets its error at once. (Found with a stackshot of Safari's threads.)
- **Wi-Fi joins a known network again by itself** (auto-join). Two things stood in the way: wifid asked for the radio to
  be powered before it was up and gave up when refused, and the driver did not answer `RSSI_BOUNDS`, so auto-join's
  minimum signal stayed at 0 dBm and every network was "below the minimum RSSI threshold". Both fixed: the phone rejoins
  within seconds of the radio coming up, or after Wi-Fi is turned off and on. (With this kit nothing is kept across
  reboots, so after a reboot a network is joined by hand once more; see below.)
- **Location, experimental** (`gnss=1`): the modem's GPS through QMI LOC, its positions handed to `locationd` and
  Location Services turned on, so Settings and Maps see a position. The path was confirmed end to end indoors with the
  modem's coarse position (`gnss_feed_any=1` hands that over too); only real fixes are handed over by default, and an
  outdoor fix has not been confirmed yet. `EXTRA="gnss=1" ./run.sh` turns it on.
- **Smoother screen, quicker start**: the widgets' extensions and the daemons behind them are kept in Darwin's background
  policy (`quietboot`; the first minutes after boot gained most), and textures the GPU can reach are filled by the GPU rather than copied by the CPU.
  Scrolling is now 55–60 frames a second with about one frame in ten late (Beta 0.2: about 50, a third late); a touch
  reaches the panel in about 35 ms end to end.
- **Diagnostics on the phone**, over SSH: `stacks PID|all` (every thread's stack and what it waits for, from the kernel's
  stackshot), `logdump SECONDS [PREDICATE]` (the system log, read on the phone), `socks [NAME…]` (a process's sockets).
- **For developers: `/private/var` kept across reboots** in a partition `darwin` cut from the end of userdata
  (`ufs_write=1 var_store=1`; saved as a run ends, about a minute, in two slots). The test kit does not make that
  partition and runs with both off; making it belongs with flashing the phone, the next release's work.

## Known issues

- Nothing on the phone survives a reboot with the kit: Wi-Fi networks and Bluetooth pairings are made again every boot.
- Scrolling is still not as smooth as an iPhone's (see above); no cameras.
- Some routers isolate their clients: if your Mac cannot reach the phone over Wi-Fi, put both on an iPhone's hotspot
  (keep the hotspot's settings page open on the iPhone while the 6T joins: an idle hotspot stops advertising itself).
- `neofetch` says "iPhone X / A11": the user space believes it is an iPhone10,3.
- Rarely, a run stops at boot with `initproc failed to start`: run it again.

# 繁體中文

仍是開發者移植，跟 Beta 0.2 一樣：

- 要用 USB 接著 Mac 開機。
- 整套系統跑在記憶體裡，不刷任何分區，重開機就回到 Android。
- 用你自己的 IPSW 和你自己手機的韌體在 Mac 上建置。
- 這裡不散布任何 Apple 軟體或原廠韌體。

**新增：**
- **Safari 能載入網頁**：Beta 0.2 開網頁會一直轉圈或空白，但網路其實是通的。
  - WebKit 早就載完、畫好了，是 Safari 主執行緒在等 AppleMediaServices；它在等 `apsd`，`apsd` 又在等 `mobileactivationd`。
  - `mobileactivationd` 在這台手機上一啟動就崩潰，排隊的請求永遠不回。現在不啟動它，問它的程式立刻拿到錯誤。
- **Wi‑Fi 會自動連回已知網路**：
  - 原因一：wifid 在電台還沒好時就要求開電源，被拒絕後就放棄。
  - 原因二：驅動沒回答 `RSSI_BOUNDS`，自動加入的最低訊號門檻停在 0 dBm，每個網路都被判「訊號太弱」。
  - 兩個都修好了；電台一起來幾秒內就會連上，關掉再打開 Wi‑Fi 也會自動連回。（用測試包時手機上的資料不會保留，重開機後還是要手動加入一次，見下方。）
- **定位（實驗中，`gnss=1`）**：數據機 GPS 經 QMI LOC 把位置交給 `locationd`，並打開定位服務，設定和地圖都看得到位置。
  - 室內用數據機的粗略位置（加 `gnss_feed_any=1` 才會交出）確認過整條路徑；預設只交出真正定位的結果，戶外定位還沒實測成功。
  - 用 `EXTRA="gnss=1" ./run.sh` 開啟。
- **畫面更順、開機後更快能用**：把小工具擴充和背後的服務一直留在背景優先權（開機頭幾分鐘改善最多）；GPU 能直接讀的貼圖改由 GPU 填，不用 CPU 複製。
  - 滑動現在每秒 55～60 幀，約一成的幀會晚到（Beta 0.2 約 50 幀、三分之一晚到）；手指到畫面約 35 ms。
- **手機上的診斷工具**（透過 SSH）：`stacks PID|all`（每條執行緒的堆疊和在等什麼）、`logdump 秒數 [條件]`（讀系統日誌）、`socks [名稱…]`（行程的網路連線）。
- **開發用：`/private/var` 跨開機保留**，存在從 userdata 尾端切出的 `darwin` 分區（`ufs_write=1 var_store=1`；一輪結束時存檔約 1 分鐘，兩個存檔槽輪流寫）。
  - 測試包不會建這個分區，也預設關閉保存；建立分區要寫入手機，留到下一版和「開機直接進 iOS」一起做。

**已知問題：**
- 用測試包時，手機上的資料不會跨開機保留：每次開機 Wi‑Fi 和藍牙配對都要重來。
- 滑動還沒有 iPhone 順（見上）；沒有相機。
- 部分路由器會隔離用戶端。Mac 連不到手機時，讓兩台都連 iPhone 熱點（6T 加入時，iPhone 要停在「個人熱點」頁，閒置的熱點會停止廣播）。
- `neofetch` 會顯示 iPhone X／A11，因為系統以為自己是 iPhone X。
- 偶爾開機會停在 `initproc failed to start`：再跑一次即可。
